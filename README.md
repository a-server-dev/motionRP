# motionRP

Minecraft **Paper 26.3 / Java 25 / BetterModel 3.6.0** 用のプレイヤーモーションプラグインです。Velocity配下ではPaper側に導入します。Velocity用の追加プラグインは必要ありません。

## v0.60.0 — 足から球へ入るキックと片手をつく着地

デスソードは蹴る前の球を足へ追従させず、地面近くの定位置へ足を振り込む前蹴りに変更しました。接触後に球が浮き、右足を前・左足を後ろに置きながら手刀の決め姿勢へ段階的につなぎます。

エターナルブリザードの両足の捻転は1回に減らしました。その後は脚を左右に大きく開き、片手を地面につき、逆腕を後ろへ上げた低い姿勢で20tick（約1秒）静止してから次の跳躍へ入ります。後半の溜めとキック、演出全体の長さは維持しています。

## v0.59.0 — デスソードの決め姿勢と氷球の両足捻転

デスソードは手刀を振り抜いた後、両足を接地したまま前後に開き、上体をひねって前へ倒し、逆側の腕を高く後ろへ伸ばす決め姿勢を維持します。

エターナルブリザードはボールをすくい上げた直後に小さく跳び、両足を前後に入れ替えて素早く捻転させます。その後、一度両足で着地してから従来の跳躍・溜め・回転キックへつなぎます。演出全体の長さは変更していません。

## v0.58.0 — 手刀と体幹の連動、氷のすくい上げと溜め

デスソードは手刀をためる間は上体を起こし、振り下ろしに合わせて腰→胸→肩がひねり戻りながら前へ入る動きへ修正しました。手刀だけで射出し、両足の接地は維持しています。

エターナルブリザードは足を球の下へ入れてすくい上げ、足から離れた後に球が頭上へ上がるよう同期しました。シュート前は蹴り脚と膝を深く引き、対角の腕と胸・腰をひねって8tickため、回転の終わりと同時に振り抜きます。全体の長さは変えていません。

## v0.57.0 — 手刀だけのデスソードと氷の回転シュート

デスソードは初動のキック後に両足を地面へ戻し、上げた手刀を6tickためてから振り下ろします。最後は脚を振らず、手刀の後だけに球を射出します。深い前傾姿勢と、球に手を触れない間隔は維持しています。

エターナルブリザードは動画を見直し、足元からの蹴り上げ→頭上で氷球へ変化→身体を傾けた空中の一回転→脚を引いて蹴り抜く流れに変更しました。身体全体を包む白青の風、飛翔時の横向きの氷の尾、大きな雪結晶を追加しています。全体の長さは約7.9秒のままです。

JAR更新・再起動後、サーバー側BetterModelの最新リソパを再適用してください。

## v0.56.0 — 接地したキックと深い前屈の手刀

デスソードの小ジャンプをなくし、左の軸足を地面につけたままヤクザキックするよう変更しました。手刀では腰と胸を合わせて約80度前へ折り、地面の物を拾うような深い前傾姿勢にしています。球はキック後に前方・低めの位置へ落ち着き、手刀の後に射出されます。

## v0.55.0 — デスソードの演出順と両脚の振り抜き

デスソードは動画を再確認し、ボールを足で浮かせる→前傾して引いた脚で蹴る→青黒い球へ変化→球の直前を手刀で斬る→刃状の尾を後ろへ広げて射出、の順に修正しました。腕を後ろへ引く姿勢・蹴った後の反動も追加し、演出全体は約6.45秒を維持しています。

ファイアトルネードは左足だけでなく右足も連動し、溜めは左足が後ろ・右足が前、蹴った後は左足が前・右足が後ろになります。

## MotionRP Studio — Webでモーションを制作

**公開先（Pages初回設定後）: https://a-server-dev.github.io/motionRP/**

bbmodelを読み込み、3Dプレビューとタイムラインでモデル配置・移動・追従・粒子・音を設定できます。簡単なモデルはChatGPT用の依頼文とJSON貼り付けで作れます。APIキーやAI料金は不要で、ChatGPT側の無料枠・ログイン制限に従います。

制作データはZIPで保存し、GitHubにログインしてPRで `projects/<id>/` へ提案します。取り込まれた作品は作品ライブラリから読み込めます。`Studio Build` がJARとBetterModelのリソパを生成し、Actionsの成果物からダウンロードできます。PRは自動マージしません。編集自体にGitHubログインは不要です。

0.42.0からデータ駆動のStudio演出を再生できます。既存モーションは維持します。詳しい手順・対応範囲・形式は [Studioガイド](docs/studio.md) を確認してください。

## 0.41.0：近くでの再生時に観覧OFF・リソパの案内

モーションの再生開始時、表示範囲内にいる観覧OFFの人へ「演出表示がOFFです」と通知します。`[表示ON]` をクリックすると `/motionrp view on` を実行できます。演者本人がOFFの場合も通知します。同一ワールド・演者が見える相手・`visibility.range` の範囲内だけが対象で、同じ人には30秒に1回まで案内します。ゴール・HRパフォーマンスは観覧OFFでも表示されるため、OFF警告は出しません。

MotionRPから送った配布パックについて、取得・適用失敗、拒否、解除を検知した場合や、旧版の適用成功後に公開パックが更新された場合は、近くでの再生時にリソパの案内も出します。`[リソパ再適用]` をクリックすると `/motionrp reload` を実行します。観覧OFFと重なった場合は1つの通知にまとめます。

手動で入れたローカルパック、別プラグインからのパックの内容までは判定できません。状態不明・ダウンロード中を「未適用」と決めつけて通知しません。判定記録は接続中のみ保持し、退出時に削除します。自動で観覧ONにしたり、パックを一斉配信したりすることはありません。

JARを交換して再起動してください。今回の変更ではモデル・リソパの更新はありません。

JARを交換して再起動してください。今回の変更ではモデル・リソパの更新はありません。

## 0.35.0：二人用アイテムと招待の承諾

フュージョンとブロリー岩盤を、通常のモーションと同じ登録GUIで使えるアイテムにしました。

```
/motionrp give motion fusion
/motionrp give motion broly
```

モーションセットに登録・選択して左クリックすると、8ブロック以内で一番近いプレイヤーへ招待します。受ける側は30秒以内に、次のいずれかで参加できます。

- `/motionrp accept` を入力

### 元のMotionRP演出の表示設定

**初期状態はOFFです。** `/motionrp view` でON/OFFを切り替え、`/motionrp view on`・`/motionrp view off` で指定できます。`motionrp.use` 権限で利用でき、設定はプレイヤーごとに保存され、再起動後も残ります。演者本人も見たい場合はONにしてください。

ONの人だけに、MotionRPが所有するプレイヤーアニメーション・分身・武器などのbbmodel・パーティクル・効果音・巨人化の雷・演出用の地面表示を送ります。途中でONにすれば進行中の演出へ参加し、OFFにすればモデルと演出用地形を解除し、新たな粒子送信を止めます。送信済みの粒子や再生済みの音は自然に消えるまで残る場合があります。既存の他プラグインのモデル表示には干渉しません。

実際のプレイヤーの位置・スケール・当たり判定はサーバー共通です。OFFでも、突進・ジャンプ・巨大化などの実際の移動やサイズの変化は見えます。巨人化でも実体を一律に透明化せず、OFF側には実際のプレイヤーを残します。外部スキンを使う旧オプションではプロフィール変更もサーバー共通です。`goalperformance`・`hrperformance` はこの設定の対象外で、従来どおり周囲へ表示します。

`plugins/MotionRP/config.yml` の `visibility.range: 48` で表示距離の上限を指定できます（8〜256ブロック、初期値48）。分身・エフェクトは各技の元々の表示範囲と設定値の小さい方を使い、本体アニメーションにも設定値を上限として適用します。ONの演者本人は、元気玉の浮上などで発動地点から離れても表示距離の対象外として自分の演出を見続けられます。同じワールド・演者が見える相手だけを対象とし、視線の方向によるカリングは引き続きBetterModel設定にも依存します。変更後は管理者が `/motionrp configreload` を実行してください。

### 0.7.0：GitHub Releases経由のリソースパック自動配布

追加のTCPポートを開かずに、**導入先サーバーで生成した実際のパック**をGitHub Releasesへ公開し、参加者へ送信できるようにしました。公開名とローカルの配布用コピー名は、ご指定の **`mortionRP.zip`** です。BetterModel側の生成元 `build.zip` はそのまま監視します。

一度だけ、次の設定を行ってください。

1. 公開設定にした既存の `a-server-dev/motionRP` を配布先に使います。別の公開リポジトリを使う場合は下の `repository` へ指定します。
2. GitHubの [Fine-grained personal access token作成画面](https://github.com/settings/personal-access-tokens/new) で、公開リポジトリ `a-server-dev/motionRP` のみを対象にし、Repository permissions の **Contents: Read and write** を許可します。組織の設定によっては承認が必要です。
3. トークンを導入先の `plugins/MotionRP/github-token.txt` へ1行で保存します。チャットやGit、`config.yml` へ貼らないでください。Linuxではファイルをサーバーの実行ユーザーだけが読める権限（600）にします。代わりにサーバープロセスの環境変数 `MOTIONRP_GITHUB_TOKEN` でも指定できます。
4. `plugins/MotionRP/config.yml` の `resource-pack.enabled` を `true` にして管理者が `/motionrp configreload` を実行します。

```yaml
resource-pack:
  enabled: true
  repository: a-server-dev/motionRP
  source-file: plugins/BetterModel/build.zip
  required: false
  prompt: MotionRPのモーション表示用リソースパックです。
```

これで、生成済みZIPを通常約5〜10秒で検知し、アップロード・公開ダウンロードのハッシュ確認後に配布可能になります。0.36.0以降は各プレイヤーが `/motionrp reload` で要求したときだけ送信します。新規参加時も自動送信しません。更新ごとにSHA-256を含む別のURLを使い、PaperへSHA-1も渡します。内容が同じなら再アップロードも定期的な再送信もしません。GitHubへのアップロード・検証はサーバーのメインスレッド外で実行します。

初回はクライアントでサーバーリソースパックを許可してください。必須にする場合は `required: true` にします。既存の `server.properties` や他プラグインのパックは保持し、MotionRP自身のパックIDだけを置き換えます。ダウンロード失敗・拒否時にはプレイヤーへ案内を表示します。

```text
/motionrp pack status
/motionrp pack publish
```

`publish` は再確認・公開を予約する管理者コマンドです。0.36.0以降は再送信しません。同じ内容でも公開先を再確認できるため、Releaseを復旧したい場合にも使えます。通常のモデル追加・BetterModel再読み込み・再起動では実行不要です。生成途中・壊れたZIPは公開しません。アップロードが失敗した場合は再試行し、前回検証したパックを保持します。公開済みのハッシュ付きReleaseを削除すると、そのURLでのダウンロードはできなくなります。

Releaseは `motionrp-pack-<SHA-256>` タグの専用プレリリースとして作成し、通常のLatest Releaseには設定しません。ファイル名は常に `mortionRP.zip` です。公開先リポジトリは認証なしでパックを取得できる必要があり、非公開リポジトリは使用できません。トークンが期限切れになった場合は差し替えてください。秘密情報はプレイヤー向けURL・保存する公開情報・ログに含めません。

再起動後に前回のパックを利用するため、検証済みコピーを `plugins/MotionRP/mortionRP.zip`、公開情報を `pack-publication.properties` に保存します。認証未設定時でも、この検証済みキャッシュがあれば以前の公開パックを案内できます。初回の認証設定前はGitHubへの公開・更新は行いません。BetterModelの出力先を変更している場合は `source-file` も合わせてください。

ZIPの上限は100MiB、展開後の合計は512MiBです。

## 操作

| 専用セットアイテムの操作 | 動作 |
| --- | --- |
| 右クリック | 9枠の登録GUIを開く |
| 左クリック | 選択中のモーションを1回再生。再生中に押すと終了 |
| シフト＋左クリック | 次の登録済み枠に切り替える。空き枠を飛ばし、最後の次は先頭 |

GUIを開いた状態で、**下の所持品のモーションアイテムをクリックすると、最初の空き枠へ1個だけ預けます**。上の登録済み枠をクリックすると、その1個を所持品へ返します。GUIを閉じても登録内容は残ります。左・右・シフトクリックはいずれも1個ずつです。ドラッグによる登録や枠の入れ替えには対応していません。

同じ定義から配布したモーションアイテムは最大64個までスタックできます。所持品が満杯で返せない場合は登録したままにし、地面には捨てません。別のアイテムやGUIの表示コピーは登録・取り出しできません。

再生中の移動・ジャンプ入力は位置固定とし、再生を続けます。向きの変更と螺旋丸の専用突進、螺旋手裏剣の専用ジャンプは許可します。有効な被ダメージ・外部からのテレポート・死亡・ログアウト・持ち替え・プラグイン停止で再生を終了します。乗車・滑空・就寝中は再生できません。

## モーションの追加

1. BetterModel用のプレイヤーモデル（`.bbmodel`）にアニメーションを作り、`plugins/BetterModel/players/` に配置します。通常のエンティティモデルではなく、プレイヤー用の骨構造を使用します。
2. BetterModelを再読み込みし、リソースパックを再生成・配布します。
3. `plugins/MotionRP/config.yml` の `motions` に定義を追加します。

```yaml
motions:
  wave:
    name: 手を振る
    model: your_player_model
    animation: wave
    max-ticks: 100
    # item-model: yourpack:wave_token
```

4. `/motionrp reload` → `/motionrp status` で確認し、`/motionrp give motion wave` で配布します。

`item-model` は任意で、アイテムの見た目を外部パックのモデルに変更できます。モデル自体やアイテム用テクスチャは別途パックに用意してください。`max-ticks` は再生が終了しなかった場合の強制終了上限（1〜12000 tick）です。通常はアニメーションの終了時に元のプレイヤー表示へ戻ります。

定義を削除しても、預けたアイテムは消さずGUIから返却できます。その定義の再生と新規登録は停止します。既存の別プラグインによるモデル表示がある場合は、勝手に閉じず、再生を拒否します。

通常の定義では `effect: none`（省略可）、螺旋丸のシーンには `effect: rasengan` を使用します。螺旋丸のプレイヤーモデルには `rasengan_helper`、球モデルには `spin` が必要です。螺旋丸の `max-ticks` は96以上にしてください。同梱モデルをサーバー上で編集した場合は上書きしないので、更新版を反映したいときは既存ファイルをバックアップして差し替え、BetterModelを再読み込みしてください。

螺旋手裏剣は `effect: rasenshuriken`・`model: motionrp_rasenshuriken`・`animation: rasenshuriken` を使用し、`max-ticks` は152以上にしてください。球モデルは `motionrp_rasenshuriken_orb`、手元の追従位置は同梱の `rasenshuriken-hand-path.csv` を使います。モデルを独自編集した場合は生成スクリプト側の姿勢と追従位置も合わせて調整してください。

王の財宝は `effect: gate_of_babylon`・`model: motionrp_gate_of_babylon`・`animation: gate_of_babylon` を指定し、`max-ticks` は116以上にします。須佐能乎は `effect: susanoo`・`model: motionrp_susanoo`・`animation: susanoo` を指定し、`max-ticks` は128以上にします。千本桜は `effect: senbonzakura`・`model: motionrp_senbonzakura`・`animation: senbonzakura` を指定し、`max-ticks` は212以上にします。新しいモデル群も `tools/generate_summons.py` で再生成できます。

## 保存

登録したアイテムの実データと選択番号を、プレイヤーのPersistentDataContainer（`motionrp:loadout_v1`）に保存します。所有者はセットアイテムではなくプレイヤーです。セットアイテムを交換しても登録は共有されます。

登録・返却・選択変更時に `Player.saveData()` を呼び、通常の所持品と預かりデータを同じプレイヤーデータに記録します。Paper 26.3で確認した保存先は `world/players/data/<UUID>.dat` です。別ファイルへの二重書き込みはありません。保存形式はバージョン・サイズ上限・チェックサムを持ち、読めないデータを空として上書きしません。バックアップはプレイヤーデータ全体を取得してください。プロセス強制終了やディスク障害に対する追加のトランザクション保証はありません。

登録は死亡後も保持します。アンインストール前にはGUIから預けたアイテムを回収してください。Velocity配下の複数Paper間でのデータ同期は含みません。

```sh
source /workspace/tooling/activate.sh

cd integration
npm ci --cache /workspace/tooling/npm-cache --ignore-scripts --no-audit --no-fund

```
